# Local acceptance mechanics — 8 November 2026

1. The original offline suite passed 37 tests. Ten request-change tests were then added: eight failed before the fix, while changed crop hash and model already invalidated correctly.
2. The dispatcher now hashes the canonical full wire body (rendered text, candidate and prior context, image bytes, model, temperature, token limits, and provider request settings), destination, provider, and timeout. Cache rows without this material-request identity are not silently reusable. Credentials and attempt IDs are excluded. All historical ledger rows remain unchanged and retain their costs.
3. The release-selection path now independently filters incompatible request identities. A changed request cannot revive an older successful decision when a later call is missing, stopped, or fails. This is not a full-workspace migration facility: version source/config changes and use new release identifiers rather than treating an existing immutable release as a refreshed result.
4. The narrow historical-reading adapter preserves original route, prompt version/hash, timestamp, source/crop hashes, exposure, and field text. Imports are explicitly historical, not dispatcher cache rows or new spending. Parser alternatives are retained, not selected. Missing metadata remains null. Legacy prompt_sha256 and model_requested field names are explicitly handled.
5. Added offline checks cover source-context changes, reading restart, downstream selection, historical provenance, and deliberate interruption after reservation and after raw persistence before ledger append. Unknown attempts stay reserved and are not automatically resent. These are exception-injection tests, not an operating-system kill or live-provider fault test.
6. Real-source data and acceptance outputs stay in the separate local evidence project, not in this code repository. No paid inference, remote configuration, or publication is part of this change.
